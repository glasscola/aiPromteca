# 프롬테카 실행 구조

## 실행
Node.js 24 이상에서 npm ci 후 npm start. Windows는 start-assistant.cmd.
선택 기능 개인 화면 http://localhost:4317/automation.html 은 127.0.0.1 에만 바인딩합니다.
공개 GitHub Pages의 메인은 원래 체크리스트와 GPT 요청문을 제공하며 개인 설정 API가 없습니다.

## 실제 자동 실행
1. 개인 화면에서 카카오 개발자 앱 설정·로그인·메시지 전송 동의
2. 테스트 발송 후 사용자가 수신 확인
3. GitHub 연결: 기존 Git 자격 증명을 메모리에서만 사용해 저장소 암호화 키 등록
4. 클라우드 실행 점검: GitHub Actions workflow_dispatch, 실제 heartbeat 저장 확인
5. 작업 저장 → 수집 미리보기 → 예약 켜기

카카오 계정과 개발자 앱 등록은 사용자만 할 수 있습니다. 로그인 없이 발송 완료로 표시하지 않습니다.
고용24는 별도 공식 채용정보 인증키가 필요합니다. 키 저장과 실제 자료 조회 성공을 구분합니다.
GPT/API를 사용하지 않는 결정적 수집기이므로 AI 분석·원문 검증·모든 채용 사이트 검색을 수행한다고 표시하지 않습니다.
뉴스는 Google 뉴스 RSS 제목·게시 시각·링크 모음입니다. 날씨는 Open-Meteo 예보입니다.
기존 30개 GPT 요청문 도구는 prompt.html에 유지됩니다. 이것을 자동화 완료로 취급하지 않습니다.

## 저장과 접근
- .assistant/key: 로컬 AES-256-GCM 암호화 키. Git 제외. 이 폴더를 잃으면 클라우드 상태를 복호화할 수 없습니다.
- .assistant/state.enc: 클라우드 연결 전 로컬 암호화 상태.
- GitHub Secrets ASSISTANT_STATE_KEY: 실행 중 복호화에 사용. 로그에 출력하지 않습니다.
- assistant-state 브랜치 state.enc: 암호화한 사용자 설정·카카오 토큰·실행 기록.
- reports/{uuid}.json: 보고서별 다른 키로 암호화된 결과. 복호화 키는 카카오 결과 링크의 URL fragment에만 포함합니다.
- 결과 링크를 공유받은 사람은 결과를 읽을 수 있습니다. GitHub 공개 저장소에는 평문 개인정보를 올리지 않습니다.
- 상태 변경은 같은 출처 Origin과 CSRF 토큰을 검사합니다. 카카오 callback은 일회용 state·브라우저 세션·10분 유효기간을 검사합니다.

## 예약과 실패
GitHub가 7·22·37·52분에 작업을 확인합니다. 정확한 정시 도착을 보장하지 않습니다.
희망 시각 이전에는 보내지 않고, 이후 6시간 범위에서 당일 한 번 실행합니다.
상태 파일의 낙관적 잠금으로 같은 슬롯의 중복 실행을 막습니다.
전송 직전 의도를 저장하고 응답 불명·중단 시 자동 재전송하지 않습니다.
미리보기 성공은 발송 성공이 아닙니다. 카카오 API 성공은 사용자의 실제 읽음 확인이 아닙니다.
공개 저장소의 예약 비활성화 정책, 외부 서비스 할당량·인증 만료·지연을 확인하세요.
요금이나 할당량 변경은 각 공식 제공처에서 확인하세요. 유료 AI 서비스는 호출하지 않습니다.
